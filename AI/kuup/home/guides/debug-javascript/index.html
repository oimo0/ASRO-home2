JavaScriptのnullエラーを、AIと一緒に切り分ける

「ボタンを押しても動かない」をそのまま相談するより、エラーが起きる行と再現手順を一緒に渡すと、原因を切り分けやすくなります。JavaScriptのボタン処理で実際に起きるパターンを追います。

ASRO · 約7分で読めます

目次

  1. エラーと該当するHTMLをセットにする
  2. 名前が合っていたら、読み込む順番を確認する
  3. 直したあと、クリックの結果まで見る

エラーと該当するHTMLをセットにする

例ではページを開いた直後に、コンソールへ「Cannot read properties of null (reading 'addEventListener')」が出ます。ボタンをクリックする前に失敗していることが、最初の手がかりです。

<button id="save">保存</button>

const button = document.querySelector("#save-button");
button.addEventListener("click", () => console.log("saved"));
質問例

ページを開いた直後、2行目のaddEventListenerでnullエラーが出ます。添付したHTMLとJavaScriptを見て、どこでnullになったか、確認方法と最小の修正を説明してください。

HTMLはidがsave、JSはsave-buttonを探しています。開発者ツールでdocument.querySelector("#save")を実行し、ボタン要素を取得できることを確かめてから、JS側を"#save"へそろえます。

名前が合っていたら、読み込む順番を確認する

セレクターが合っていても、head内の通常のscriptが先に実行されると、bodyのボタンはまだ作られていません。同じセレクターをコンソールで後から実行すると取得できるのに、ページ起動時だけnullなら、タイミングが候補です。

<!-- 外部の通常スクリプトなら、headからdeferで読み込む方法があります -->
<script defer src="./app.js"></script>

通常の外部スクリプトに付けたdeferは、HTMLの解析を待ってから実行するために使えます。単にbutton?.addEventListener(...)としてエラーを消すと、保存ボタンが必要な画面で処理が登録されないまま見逃すことがあります。要素が存在する前提なら、取得できない理由を確認します。

直したあと、クリックの結果まで見る

  • 再読み込みして、起動時のエラーが消えたかを確認する。
  • ボタンを一度クリックして、期待したログが一度だけ出るかを見る。
  • エラーが消えても動かなければ、イベントの種類、別のオーバーレイ、ボタンのdisabled属性を確認する。

AIに渡す際は、小さく切り出した再現コードで十分です。実サービスのAPIキー、ログイン情報、利用者データは除き、URLや値は再現に必要なものだけ残しましょう。
